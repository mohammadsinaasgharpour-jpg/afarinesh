# Security addendum, 2026-11-12

Covers the changes made after `POST_REMEDIATION_REPORT.md`: database storage in Supabase, step-by-step forms, the privacy page and the redesign. Method: source review of the changed files, live calls to the new database function with synthetic data, the Supabase security advisor, `npm audit`, and the unit and browser test suites. Cloudflare's security-audit skill was read and used as review guidance; its full multi-agent, sandboxed mode was not run.

## What changed

| Area | Change |
|---|---|
| Storage | Forms are stored in `school.form_submissions` (Supabase project `dtqwxyfxemnkautcufho`). The schema is not exposed by the API, row level security is on with no policies, and all table rights are revoked from `anon` and `authenticated` |
| Write path | `public.submit_form(kind, id, data)`: whitelists fields per form, checks types, lengths and formats, counts repeats per phone or national ID and per form per hour in the database, then inserts |
| Server | `server/forms.mjs`: `createSupabaseStore`, `storeThenNotify`. The Vercel functions store first, then announce in Telegram; a failed announcement no longer loses a form |
| Validation | Names, address, school and messages must be Persian; placeholder phone numbers are refused; birth date comes from three lists. Same file runs in the browser and on the server |

## Findings

| ID | Severity | Finding | Status |
|---|---|---|---|
| SEC-03 | was Medium | Rate limits were per server instance on Vercel | Fixed: per-person and per-form limits are now counted in the database |
| SEC-14 | Medium | `submit_form` is callable by anyone holding the public key, without going through the site. They cannot read anything, but they can store junk that passes the format checks and can use up a form's 120-per-hour allowance, which would turn real families away for that hour | Open. Fix: set `SUPABASE_SECRET_KEY` in the Vercel project (the server already prefers it), then run `revoke execute on function public.submit_form(text, uuid, jsonb) from anon;` |
| SEC-15 | Low | `public.rls_auto_enable()` exists in the project (not created by this work) and is a `SECURITY DEFINER` function callable by `anon` and `authenticated` | Open: owner to confirm what it is and revoke public execute |
| SEC-16 | Low | Retention is promised on the privacy page (12 months) and `school.purge_old_submissions()` exists, but the daily schedule (pg_cron) was not created because the permission check blocked it | Open: owner to approve the schedule |
| SEC-04 | Medium | Copies of forms also go to the Telegram channel, which has its own history and members | Open (school policy), unchanged |
| SEC-12 | Medium | Node.js 26.7.0 on the development machine has known high-severity issues | Open: upgrade to 26.12.1 or later |

Two synthetic rows from testing remain in the table (`dedupe_key` 09170000001, name «آزمون سامانه»); deleting them was declined by the permission prompt.

## The 12-point pre-launch list

| # | Check | Result |
|---|---|---|
| 1 | Login, hashed passwords | Not applicable: the site has no accounts |
| 2 | API keys only on the server | Telegram token only in host settings; the Supabase key in code is public by design (see SEC-14) |
| 3 | Database access rules | No read path at all for site visitors |
| 4 | HTTPS, server-side checks | HSTS on; every form is validated on the server and again in the database |
| 5 | XSS, parameterized queries | Text is cleaned and written with `textContent`; CSP without inline scripts except one hashed; the database function uses no dynamic SQL |
| 6 | Rate limit, CSRF | Per IP, per person and per form; Origin check and JSON-only requests |
| 7 | Cookies, reset links | Not applicable: no cookies or passwords |
| 8 | File uploads | Not applicable: none |
| 9 | Admin pages, price checks | Not applicable: none |
| 10 | Debug off | Errors return a code only; ids, not personal data, in logs |
| 11 | Packages | No runtime dependencies; `npm audit` clean |
| 12 | Git history | No secrets found |
