# وب‌سایت دبیرستان آفرینش شیراز

بازطراحی کامل afarineshshiraz.ir: یک صفحه‌ی سریع و دسترس‌پذیر، بدون وردپرس؛ در اجرا هیچ وابستگی npm ندارد (Playwright فقط برای تست است).

## اجرا

```bash
npm start          # http://127.0.0.1:8080
npm test           # تست‌های واحد و یکپارچگی (node:test)
npm run test:ui    # تست‌های رابط کاربری در Chrome، دسکتاپ و موبایل (Playwright)
npm run build      # فهرست دبیران، صفحه‌های فرم (content/pages) و vercel.json
npm run build:images   # تبدیل عکس‌های source-images/ به WebP (نیاز به Python + Pillow)
```

متغیرهای محیطی: `PORT`، `HOST`، `PUBLIC_DIR`، `DATA_DIR`.

## ساختار

| مسیر | کار |
|---|---|
| `public/` | فرانت‌اند ایستا: HTML، CSS، JS، فونت و تصاویر WebP |
| `public/assets/js/validate.js` | اعتبارسنجی مشترک فرم، هم در مرورگر و هم در سرور |
| `server/app.mjs` | سرور: فایل‌های ایستا (فشرده‌سازی br/gzip، ETag، کش) و API |
| `content/team.json` | داده‌ی دبیران؛ پس از ویرایش `npm run build` بزنید |
| `source-images/` | عکس‌های اصلی سایت قبلی؛ ورودی `build:images` |
| `content/pages/` | قالب صفحه‌های پیش‌ثبت‌نام و دعوت به همکاری؛ سربرگ و فوتر از index.html پر می‌شود |
| `server/forms.mjs` | پردازش امن هر سه فرم: اعتبارسنجی، محدودیت درخواست، ضد ربات، ارسال به تلگرام |
| `api/` | تابع‌های Vercel: `inquiries`، `pre-registration`، `careers`، `health` |
| `data/*.jsonl` | فرم‌های ثبت‌شده در اجرای محلی یا روی هاست خودمان (در git نیست) |
| `research/hosting-plan.md` | برنامه‌ی انتقال به هاست مدرسه، HTTPS و پایگاه داده |

## صندوق فرم تماس (تلگرام)

روی Vercel هر درخواست تماس به‌صورت پیام به یک گروه یا کانال تلگرام فرستاده می‌شود. تا وقتی این دو متغیر تنظیم نشده‌اند، فرم به والدین پیام «با ۰۷۱-۳۲۲۹۳۱۹۴ تماس بگیرید» نشان می‌دهد و هیچ درخواستی بی‌صدا گم نمی‌شود.

1. در تلگرام به `@BotFather` پیام دهید، `/newbot` را بزنید و یک نام انتخاب کنید. توکن را جایی ذخیره کنید و به کسی نفرستید.
2. ربات را به گروه کارکنان مدرسه اضافه کنید و یک پیام در گروه بفرستید.
3. در مرورگر خودتان `https://api.telegram.org/bot<توکن>/getUpdates` را باز کنید؛ عدد `chat.id` گروه (معمولاً با `-100` شروع می‌شود) را بردارید.
4. در Vercel: پروژه‌ی afarinesh-site ← Settings ← Environment Variables، دو متغیر `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` را برای Production اضافه کنید و یک بار Redeploy بزنید.

## ویرایش محتوا

- **دبیران:** `content/team.json` (ترتیب فایل همان ترتیب نمایش است)، عکس‌ها در `source-images/` و فهرست آن‌ها در `scripts/build_images.py`. بعد `npm run build:images` و `npm run build`.
- **متن‌ها، پرسش‌ها و ساعت کاری:** مستقیم در `public/index.html`. اگر پرسشی عوض شد، بلوک `FAQPage` در `<head>` را هم هماهنگ کنید.
- **حالت روشن و تاریک:** از ساعت ۶ تا ۱۸ روشن و از ۱۸ تا ۶ تاریک، بر اساس ساعت دستگاه بازدیدکننده. دکمه‌ی ماه/خورشید فقط برای همان بازدید تغییرش می‌دهد. اسکریپت آن در `<head>` است و بعد از هر تغییرش باید `npm run build` اجرا شود تا هش CSP به‌روز شود (تست‌ها این را چک می‌کنند).

## فرم‌ها

| فرم | صفحه | API | محدودیت |
|---|---|---|---|
| درخواست تماس مشاور | بخش تماس صفحه‌ی اصلی | `POST /api/inquiries` | ۵ بار در ۱۰ دقیقه از هر IP، ۲ بار در ساعت برای هر شماره |
| پیش‌ثبت‌نام ۱۴۰۶–۱۴۰۷ | `/pre-registration` | `POST /api/pre-registration` | ۴ بار در ساعت از هر IP، یک بار در روز برای هر کد ملی |
| دعوت به همکاری | `/careers` | `POST /api/careers` | ۳ بار در ساعت از هر IP، یک بار در روز برای هر شماره |

همه: فقط JSON، سقف حجم، بررسی Origin، فیلد تله و زمان پر کردن برای ربات‌ها، پاک‌سازی متن (حذف HTML و نویسه‌های کنترلی)، سقف کلی ۱۲۰ پیام در ساعت برای کانال، و هیچ اطلاعات شخصی در لاگ. سؤال‌های پیش‌ثبت‌نام و همکاری همان سؤال‌های فرم‌های قبلی پرس‌لاین است. روی Vercel شمارنده‌ها در حافظه‌ی هر نمونه است و تضمین کامل نیست؛ روی هاست خودمان (یک پروسه) دقیق است. IP فقط از هدر پروکسی مورد اعتماد خوانده می‌شود (`TRUST_PROXY=vercel` یا `proxy`).

## API

- `POST /api/inquiries` با JSON `{parentName, phone, grade, message}` → `201`، یا `422` با خطای هر فیلد، `503` وقتی صندوق تلگرام تنظیم نشده یا در دسترس نیست، `429` بعد از ۵ درخواست در ۱۰ دقیقه از یک IP، `413`/`415`/`403` برای بدنه‌ی بزرگ، نوع نادرست یا Origin دیگر. فرم‌هایی که کمتر از ۳ ثانیه بعد از باز شدن صفحه ارسال شوند (ربات) بی‌صدا نادیده گرفته می‌شوند.
- `GET /api/health` → `{ok: true}`

## امنیت

محدودیت ۵ درخواست در ۱۰ دقیقه روی Vercel در حافظه‌ی هر نمونه‌ی تابع است و تضمین کامل نیست؛ برای محدودیت سراسری از Firewall داشبورد Vercel یک Rate Limit روی `/api/inquiries` بگذارید.

CSP سخت‌گیرانه (هش اسکریپت درون‌خطی هنگام شروع سرور حساب می‌شود)، HSTS، `nosniff`، `frame-ancestors 'none'`، جلوگیری از path traversal، محدودیت حجم بدنه، rate limit، فیلد honeypot برای ربات‌ها، و خروجی بدون HTML خام در کلاینت.

## استقرار

**Vercel (فعلی):** `npx vercel deploy --prod` از ریشه‌ی پروژه؛ تنظیمات در `vercel.json` و فایل‌های ارسالی با `.vercelignore` محدود می‌شوند.

**سرور خودتان:** پشت Nginx/Caddy با HTTPS معتبر (گواهی فعلی دامنه باطل شده و باید با Let's Encrypt تمدید شود). پوشه‌ی `public/assets/` را می‌توان از CDN سرو کرد. برای پایداری، `node server/index.mjs` را با systemd یا pm2 اجرا کنید و از `data/` نسخه‌ی پشتیبان بگیرید.
